# OpenWPS Architecture

## Project Architecture
The project follows a feature-based structure to ensure scalability and maintainability:
- `lib/core/`: Contains application-wide configuration like theme, routing, reusable widgets, and common utilities.
- `lib/features/`: Contains independent modules (Home, Files, Create, Writer, etc.) encapsulating their own UI and local logic.
- `lib/storage/`: Provides abstraction layers for data persistence, ensuring separation from the UI.

## Feature Structure
Features are isolated. For example, `home` handles the recent dashboard, while `files` manages the directory explorer. They communicate via shared services and standard routing.

## Design System
The design system (implemented in `lib/core/theme/`) is rooted in "Corporate Modernism" and "Indigo Primary", faithfully mapped from the Stitch `DESIGN.md`. It includes tokenized colors, typography (Inter), and reusable widgets (`FileCard`, `PrimaryButton`, etc.) to prevent UI fragmentation.

## Storage Strategy
The application operates on a local-first principle. The `DocumentStorage` interface abstracts all file operations. Currently, `LocalDocumentStorage` provides in-memory mock implementation, which will be replaced by local device storage (`path_provider`) in future phases.

## Navigation Strategy
We use standard Flutter `Navigator` with named routes generated by `AppRouter`. The primary scaffold (`ResponsiveScaffold`) dynamically renders a `BottomNavigationBar` on phones and a `NavigationRail` on tablets based on screen constraints.

## Future Integration Plans
- **Document Engine:** Will be integrated into `lib/features/writer/`, `lib/features/spreadsheet/`, etc., utilizing the `DocumentStorage` abstraction to read/write specific file formats.
- **Google Drive:** Will be added as a concrete implementation of `DocumentStorage` (e.g., `DriveDocumentStorage`), allowing seamless integration into the existing `FilesScreen`.
- **AI Integration:** Slated for `lib/features/ai/` handling text summarization and generation locally or via BYOK APIs without requiring our own backend.

## Constraint Adherence
- No backend server is implemented or required.
- Everything relies on local processing and storage abstraction.
